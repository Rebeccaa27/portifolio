01 / AGENDAMENTOSIntegração entre sistemas

Da reserva ao lembrete.
Uma jornada conectada.

Desenvolvi uma integração entre o Cal.com, o banco de dados e a plataforma de atendimento. O fluxo acompanha os eventos da agenda e envia mensagens de confirmação, cancelamento, reagendamento e lembretes nos momentos definidos.

O que fiz e como funciona +

O problema que orientou o projeto

A comunicação precisa acompanhar a agenda: uma nova reserva exige confirmação; uma mudança de horário ou um cancelamento também precisa ser informado. Além disso, os compromissos próximos precisam ser identificados para o envio dos lembretes.

O que construí

Montei no n8n um fluxo acionado por webhook para receber os eventos do Cal.com e direcionar cada situação para o caminho correspondente. Integrei o envio das mensagens à plataforma de atendimento por API e preparei uma rotina separada para consultar os agendamentos no banco de dados.

A lógica dos lembretes

A rotina é executada a cada cinco minutos. Ela busca os registros de agendamento e verifica quais compromissos estão nas janelas previstas: no dia, uma hora antes e dez minutos antes. Cada janela tem seu próprio caminho de envio de mensagem.

O que a solução entrega

Uma comunicação conectada aos eventos da agenda e uma rotina programada de lembretes. O projeto reúne webhooks, consultas ao banco, condições de execução e chamadas de API em um mesmo processo de atendimento.

O caminho da automação

  1. O evento de agendamento chega do Cal.com via webhook.
  2. O fluxo identifica se é confirmação, cancelamento ou reagendamento.
  3. A mensagem correspondente é enviada à plataforma por API.
  4. Em paralelo, a rotina periódica consulta a agenda e aciona os lembretes.

02 / ATENDIMENTOLógica em JavaScript

O primeiro contato,
com o caminho certo.

Criei uma triagem no n8n com verificação em JavaScript para distinguir novos contatos de quem já estava na base. Para os novos contatos, o fluxo conduz a apresentação, coleta nome e cidade e prepara o encaminhamento ao atendimento.

O que fiz e como funciona +

O problema que orientou o projeto

Aplicar a triagem inicial apenas a novos contatos. Para isso, o fluxo precisa consultar as informações existentes antes de decidir se deve iniciar a coleta de dados, evitando tratar todo contato recebido como uma nova entrada.

O que construí

Organizei a entrada por webhook, o tratamento dos dados e as consultas ao contato e ao histórico. Implementei em JavaScript a verificação que determina se o contato é novo e a análise do estado da conversa para direcionar o próximo passo.

Como a conversa avança

O fluxo utiliza caminhos diferentes para apresentação, nome e cidade. Conforme as respostas chegam, salva as informações e atualiza as etiquetas: identifica a passagem pelo bot e, ao concluir a coleta, sinaliza que o contato aguarda atendimento.

O que a solução entrega

Um processo de entrada com critérios definidos para iniciar e avançar na triagem. O projeto demonstra o uso de JavaScript dentro do n8n, consultas via API, leitura de histórico e roteamento condicional aplicado a uma necessidade real de atendimento.

O caminho da automação

  1. O webhook recebe o evento e o fluxo verifica a origem da mensagem.
  2. As consultas recuperam o contato e o histórico disponível.
  3. A lógica em JavaScript identifica se a triagem deve seguir e em qual etapa.
  4. Nome, cidade e etiquetas são atualizados para o encaminhamento.
n8n · JavaScript · Webhooks · API do Atende Direito
03 / OPERAÇÃORegras de negócio

Pipeline organizado.
Uma etapa a menos à mão.

Automatizei a exclusão de cards quando o contato é movido para uma etapa específica no Atende Direito. O fluxo localiza o registro correto, verifica se há um card disponível e executa a remoção por API.

O que fiz e como funciona +

O problema que orientou o projeto

A operação utiliza uma etapa específica do pipeline como condição para remover o card. A automação precisa transformar essa movimentação em uma ação, encontrando o registro associado ao contato antes de solicitar a exclusão.

O que construí

Montei um fluxo que recebe o evento por webhook e verifica a presença do identificador do negócio. Quando esse identificador está disponível, consulta o negócio; quando não está, busca os cards associados ao contato. Os dois caminhos preparam os itens para a verificação seguinte.

Como tratei os caminhos possíveis

Após a consulta, uma condição verifica se algum card foi encontrado. Se houver card, o fluxo faz a chamada de exclusão via API. Se não houver, responde ao webhook sem executar a exclusão. Isso permite lidar explicitamente com as duas situações.

O que a solução entrega

A remoção do card vinculada a uma regra da operação, com busca por diferentes identificadores e tratamento para ausência de registros. O projeto demonstra integração por API e transformação de uma regra de negócio em lógica executável.

O caminho da automação

  1. O contato é movido para a etapa definida e o webhook é acionado.
  2. O fluxo escolhe a busca pelo negócio ou pelos cards do contato.
  3. Uma condição verifica se a consulta encontrou algum card.
  4. O card encontrado é excluído; sem resultado, o fluxo encerra sem exclusão.
n8n · Webhooks · APIs · Condicionais

01 / ESTE PORTFÓLIO

Meu trabalho, em uma experiência interativa.

Desenvolvi este portfólio com apoio do Codex para apresentar minhas automações de forma visual. Parti dos meus próprios projetos e prints, defini o que precisava ser explicado e orientei as mudanças de layout, cores, tamanho das imagens e navegação.
